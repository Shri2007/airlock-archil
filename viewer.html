Airlock

Can a malicious issue trick a tool into stealing secrets?

The task: summarize the repository’s GitHub issues.

The attack: an issue contains instructions to read credentials and send them to an attacker.

The test: Airlock runs the tool in disposable workspaces with fake secrets and different conditions. It flags unauthorized behavior before deployment.

“Betrayed” means: the tool followed the attacker’s instructions instead of sticking to the user’s task.

Sample data — these tiles illustrate the demo. They are not results from actual test runs.
Each tile = one combination of conditions. Green / PASS = no violation recorded. Red / BLOCK = violation flagged. Hover or focus for the reason. ON / OFF = whether a condition is enabled.
